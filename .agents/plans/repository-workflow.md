# Repository workflow setup

## Objective and scope

Establish the root instruction entry point, agent context, standards, eight local skills, human documentation index, and Git ignore rules on the existing repository. Preserve existing product requirements. Application code, dependencies, runtime configuration, and cloud setup are outside this work.

## Steps and acceptance

1. Inspect the current context and Git changes. Consolidate repository-wide instructions at the root and correct legacy paths.
2. Add focused rules, state and preferences, and task-specific skills with valid manifests. Use Codex's repository skill layout and keep shared context free of private material.
3. Add a human-readable project status and docs index. Ignore private agent scratch and real environment files while allowing safe example files.
4. Verify paths, relative links, manifests, Markdown structure, and Git whitespace. Check for unintended file changes and record any verification gaps.

The work depends on write access to the repository and the existing Codex skill guidance. Main risks are loss of requirements during consolidation and confusion between proposed verification commands and commands actually available. Preserve requirements in project context and verify completion with repository checks.
