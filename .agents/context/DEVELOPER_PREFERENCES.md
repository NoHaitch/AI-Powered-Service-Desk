# Developer preferences

- Build a public portfolio project through small end-to-end slices. Keep code professional, readable, maintainable, and reproducible.
- Use Bun for Node ecosystem tooling. Prefer reusable code and clear separation of responsibilities, using MVC or a similar structure where appropriate. Keep comments focused on non-obvious details.
- Before release, measure how many concurrent users and requests per second the backend can sustain.
- Use documentation to clarify requirements and decisions, and update it as behavior changes. Include appropriate tests and report actual verification and limitations.
- Prefer open-source or adequate free-tier options and a local path without mandatory spending. Discuss paid services before considering adoption.
- Explain unfamiliar AI engineering concepts when introduced. Tie technology choices to a project need and discuss meaningful alternatives and trade-offs. Prefer LangChain and LangGraph when technically justified.
- Exercise judgment on routine implementation details. Discuss consequential architecture, security, API contracts, cost, and irreversible decisions.
- Use technically precise, proportionate communication. Label proposals, assumptions, verified behavior, and unresolved questions clearly.
